# 체험 설계 원칙

캠퍼스하이의 모든 체험(이론 퀴즈, 진짜 수업 체험, 학과군 실습, 졸업 과제)은 이 원칙을 따른다. 새 체험을 만들거나 고칠 때, 그리고 별도 에이전트가 검토할 때 이 문서를 기준으로 삼는다(2026-11-10 사용자 결정).

## 누구를 위한 체험인가

- 사용자는 **고등학생**이다. 대학 용어를 모르는 것이 당연하고, 몰라도 된다.
- 체험은 **찍먹**이다. 대학 수업을 미리 공부시키거나 시험 보는 것이 아니다.

## 체험이 끝나면 학생이 가져가야 하는 것

1. **활동에 대한 감**: "이 과목에서는 이런 걸 하는구나."
2. **해본 느낌**: "이 활동, 해보니 재밌다 / 나랑 안 맞는다."
3. **아는 것과의 연결**: "고등학교 때 배운 이게 여기로 이어지는구나." (예: 미분 → 미분방정식은 '변하는 것의 규칙'을 찾는 수업)
4. **쓸 수 있는 한 줄**: 위 판단을 진로 기록·면접에 쓸 수 있는 문장.

용어 뜻을 맞히는 것은 이 네 가지 중 어디에도 해당하지 않는다. "라플라스 변환"이라는 이름을 아는지는 학생이 학과와 맞는지 판단하는 데 도움이 안 된다.

## 규칙

1. **외워야만 풀리는 문제는 두지 않는다.** 대학 용어의 뜻을 알아야만 맞힐 수 있으면 안 된다. 수업의 진짜 대상(실제 함수 이름, 실제 SQL, 실제 알고리즘)은 그대로 보여 줘도 되지만, 화면의 정보(규칙 설명, 표, 영어 단어의 뜻)로 추론해서 풀 수 있어야 한다. 정의를 외워야 하는 이름은 체험을 끝낸 뒤 "이걸 대학에서는 ○○라고 불러요"처럼 이름표로만 붙인다.
2. **모든 문제는 고등학교 수준 지식과 화면에서 방금 본 것만으로 풀 수 있어야 한다.** 화면 밖의 사전지식이 있어야 풀리는 문제는 두지 않는다. 규칙이 필요하면 문제 앞에 먼저 보여 주고, 학생은 그 규칙을 적용해 본다.
3. **한 문장으로 말할 수 있어야 한다.** 한 과목 체험을 끝낸 학생이 "이 수업은 ○○를 하는 수업"이라고 말할 수 있어야 한다. 그래서 과목마다 그 한 문장을 정해 두고 체험 끝에 보여 준다.
4. **고등학교와의 연결을 보여 준다.** 과목마다 어떤 고등학교 내용(교과·단원 또는 일상 경험)에서 이어지는지 정해 두고, 체험 안에서 그것을 출발점으로 쓴다.
5. **핵심 아이디어를 직접 느끼게 한다.** 용어를 가르치고 확인하는 것이 아니다. 그 수업의 핵심 아이디어를 고등학교 수준의 예시로 손으로 해보게 한다.
   - 예) 미분방정식: "커피가 식는 속도는 지금 온도에 따라 달라요. 10분 뒤 온도는?" 같은 일상 상황에서 '변화의 규칙으로 미래를 예측한다'를 체감한다. 끝나고 "이게 대학에서 배우는 미분방정식이에요"라고 이름을 붙인다.
6. **활동은 실제 수업에 근거한다.** 무엇을 해보게 할지는 강의계획서와 실제 과제·실습 자료(`학과데이터/`, 출처는 `backend/SOURCE.md`)에서 고른다. 수업에 없는 활동을 지어내지 않는다.
7. **맞히고 틀린 것으로 성적·해금을 정하지 않는다.** 이수는 체험을 끝까지 해보고 한 줄 기록을 남긴 것(P)이다. 맞힌 수는 학생에게 돌려주는 반응일 뿐이다.
8. **기록은 판단을 돕는다.** 한 줄 기록은 "재밌었다/안 맞았다"와 그 이유를 남기게 하고, 진로 기록에 옮겨 쓸 수 있게 이끈다.

## 이런 느낌 (사용자가 준 기준 예시, 2026-11-10)

간단하고 누구나 풀 수 있는데, 풀고 나면 그 수업에서 무엇을 배우는지 감이 온다.

- **1학년 웹/파이선프로그래밍**: 설명에 맞는 함수를 고른다. "입력 문자열의 길이 반환 → `len()`", "공백을 기준으로 끊어낸 리스트 반환 → `split()`", "모든 글자 대문자화 → `upper()`", "출력 → `print()`", "문자열에서 사용된 개수 → `count()`". 보기는 블록으로 감싸서 듀오링고처럼 빈칸으로 끌어다 놓는다. 함수 이름이 영어 단어(length, split, upper, print, count)라 처음 봐도 추론할 수 있다.
- **2학년 알고리즘**: 버블 정렬 규칙("첫 번째 원소부터 인접한 두 값을 비교해 순서가 맞지 않으면 자리를 바꾼다")을 먼저 보여 주고, `[5, 1, 4, 2, 8]`을 오름차순으로 1회전 한 결과를 고른다(정답 `[1, 4, 2, 5, 8]`). 규칙만 따라가면 풀린다.
- **3학년 데이터베이스**: 사원 표(사원번호·이름·부서·급여)를 보여 주고 `SELECT NAME FROM EMPLOYEE WHERE EMP_ID = 102;`의 결과를 묻는다(정답 이영희). SQL이 영어 문장처럼 읽혀서 표만 보면 풀리고, "표에서 원하는 값을 꺼내는 수업"이라는 감이 온다.

공통점: 풀 정보가 화면에 다 있고, 수업의 진짜 대상을 그대로 쓰고, 한 문제가 곧 "이 수업에서 하는 일"이다.

## 별도 에이전트 검토 기준

AI가 쓴 체험 데이터는 그것을 쓰지 않은 에이전트가 아래를 모두 확인한 뒤에만 공개한다.

| 기준 | 질문 |
| --- | --- |
| 근거 | 활동과 설명이 강의계획서·실제 과제 원문과 맞는가? 지어내거나 과장한 곳이 없는가? |
| 정답 | 정답이 하나로 정해지고 맞는가? (체험에 정답이 있다면) |
| **대상 적합성** | **고1 학생이 사전지식 없이, 화면에 보이는 것만으로 이해하고 풀 수 있는가?** |
| 용어 | 대학 용어의 뜻을 외워야만 맞힐 수 있는 문제가 있는가? (화면 정보로 추론할 수 없으면 실패) |
| 한 문장 | 체험을 마친 학생이 "이 수업은 ○○를 하는 수업"이라고 말할 수 있는가? |
| 연결 | 고등학교 내용과의 연결이 보이는가? |
| 문구 | 한국어가 자연스럽고 고등학생이 읽기 쉬운가? |

대상 적합성은 검토자가 "고1 학생 역할"로 직접 풀어 보고 판단한다. 막힌 문제와 이유를 남긴다.
