## 계약

공개 `/api/me` 형식은 유지하고 내부 세션 조회만 사용자 ID를 얻는다. `/api/me/records`는 내부 ID 대신 서명키로 만든 계정 scope, revision, 서버 상태를 반환한다. 브라우저는 scope를 요청에 되돌려 보내며 서버가 세션 소유자와 비교한다. 계정 전환 직후의 이전 큐가 다른 계정으로 저장되지 않는다.

`record_rules.py`: `imported(state, raw, server_catalog, server_now)`, `apply_operation(state, operation, server_catalog, server_now)`가 규칙을 소유한다. `records.py`가 인증·입력 검사·revision 충돌 재시도를 맡는다. `commit_account_records`가 revision 비교·요청 UUID 중복 제거·문서 교체를 단일 트랜잭션으로 처리한다.

전체 스냅샷 병합은 과목 이수 횟수를 합치지 못하고 삭제한 학과를 되살릴 수 있어 제외했다. 명령은 enroll/profile/complete/note/draft/leave/reset/preferences로 제한한다. complete에는 이번 시도 점수를 보내며 서버가 등급·최고 성적·횟수·7일 지급 제한을 계산한다. 가져온 기록은 imported로 구분하고 크레딧·creditedAt은 가져오지 않는다.

사진은 기존 256px JPEG를 유지하되 서버에서도 디코딩·크기 검사·재인코딩한다. 작은 MVP에서 파일 업로드와 프로필 저장이 따로 실패하지 않도록 비공개 계정 문서에 원자적으로 보관한다. 외부 이미지 URL·공개 버킷을 사용하지 않으며 사진 문자열은 각 일반 변경마다 다시 전송하지 않는다.

로그인 전 기록은 별도 게스트 저장소, 로그인 후 사본과 큐는 계정 scope별 저장소를 쓴다. 서버에 저장된 것처럼 성공을 표시하지 않고 저장 중/연결되면 저장/오류를 구분한다. 프로필 저장 실패는 편집 내용을 유지한다. 로그아웃은 먼저 큐 전송을 시도하고, 실패하면 사용자가 미저장 기록 포기를 확인한 뒤에만 세션을 끝낸다.

기존 수업은 정답을 포함한 문제를 브라우저에 보내고 결과를 브라우저에서 계산한다. 서버는 점수 형식·과목·학년·지급 규칙을 검사하지만 실제 학습 수행을 증명하지는 않는다. 실제 체험 증명은 서버가 발급한 문제·시도와 답안 채점을 별도로 도입해야 한다.
