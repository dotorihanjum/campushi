## 계약

공개 `/api/me` 형식은 유지하고 내부 세션 조회만 사용자 ID를 얻는다. `/api/me/records`는 내부 ID 대신 서명키로 만든 계정 scope, revision, 서버 상태를 반환한다. 브라우저는 scope를 요청에 되돌려 보내며 서버가 세션 소유자와 비교한다. 계정 전환 직후의 이전 큐가 다른 계정으로 저장되지 않는다.

`record_rules.py`: `imported(state, raw, server_catalog, server_now)`, `apply_operation(state, operation, server_catalog, server_now)`가 규칙을 소유한다. `records.py`가 인증·입력 검사·revision 충돌 재시도를 맡는다. `commit_account_records`가 revision 비교·요청 UUID 중복 제거·문서 교체를 단일 트랜잭션으로 처리한다.

전체 스냅샷 병합은 과목 이수 횟수를 합치지 못하고 삭제한 학과를 되살릴 수 있어 제외했다. 명령은 enroll/profile/complete/note/draft/leave/reset/preferences로 제한한다. complete에는 이번 시도 점수를 보내며 서버가 등급·최고 성적·횟수·7일 지급 제한을 계산한다. 가져온 기록은 imported로 구분하고 크레딧·creditedAt은 가져오지 않는다.

사진은 기존 256px JPEG를 유지하되 서버에서도 디코딩·크기 검사·재인코딩한다. 작은 MVP에서 파일 업로드와 프로필 저장이 따로 실패하지 않도록 비공개 계정 문서에 원자적으로 보관한다. 외부 이미지 URL·공개 버킷을 사용하지 않으며 사진 문자열은 각 일반 변경마다 다시 전송하지 않는다.

로그인 전 기록은 별도 게스트 저장소, 로그인 후 사본과 큐는 계정 scope별 저장소를 쓴다. 서버에 저장된 것처럼 성공을 표시하지 않고 저장 중/연결되면 저장/오류를 구분한다. 프로필 저장 실패는 편집 내용을 유지한다. 로그아웃은 먼저 큐 전송을 시도하고, 실패하면 사용자가 미저장 기록 포기를 확인한 뒤에만 세션을 끝낸다.

기존 수업은 정답을 포함한 문제를 브라우저에 보내고 결과를 브라우저에서 계산한다. 서버는 점수 형식·과목·학년·지급 규칙을 검사하지만 실제 학습 수행을 증명하지는 않는다. 실제 체험 증명은 서버가 발급한 문제·시도와 답안 채점을 별도로 도입해야 한다.

## 저장·충돌·로그아웃 세부 규칙

- 대기 명령은 `campushi-account-v1:<scope>:<operation UUID>`마다 독립된 항목으로 저장한다. 창 복제로 sessionStorage가 복사돼도 다른 명령을 덮어쓰지 않는다. 새로 열면 같은 계정의 미전송 명령을 복구하며 서버 UUID 중복 제거로 재지급을 막는다.
- 프로필은 서버 성공 후 편집창을 닫는다. 수정 충돌은 최신 프로필을 불러오고 편집 내용은 유지한다. 일반 수업 변경은 프로필을 덮어쓰지 않는다.
- 가져오기 응답이나 느린 저장 응답이 나중에 와도 더 낮은 revision으로 화면을 되돌리지 않는다. 다른 계정으로 바뀌면 진행 중 체험 결과와 이전 사진을 화면에서 숨긴다.
- 로그아웃은 같은 저장소의 다른 창이 새 변경을 추가하지 못하도록 먼저 잠근 뒤 대기 명령을 보낸다. 실패하면 포기 확인 또는 취소를 받는다. 세션 종료 실패 시 로그아웃했다고 표시하지 않는다. 성공 후 계정 명령·프로필·기록·화면 스택을 비운다. 아직 이전하지 못한 게스트 원본은 보존한다.
- 서버가 거절한 오래된 오프라인 명령도 자동 삭제하지 않는다. 다시 시도하거나 미저장 경고를 확인하고 로그아웃할 수 있다.
- 과거 이수 조건 예외는 `backend/data/record_conditions.json`이 기준이다. 프론트와 서버가 같은 재공개 과목 목록을 읽고 알려진 과목의 과거 예외만 복구한다. 임의 과목의 잠금 예외를 가져오지 않는다. 게스트의 성적·과거 예외는 이전용 자기 신고 기록이며 실제 수행 증거로 취급하지 않는다.
- 크레딧은 `account_credit_ledger` 합계다. 브라우저 잔액·지급 시각은 버린다. 현재 체험을 마치면 서버 시각으로 과목별 7일 간격을 적용해 5를 지급한다. 가져온 과목도 로그인 후 처음 정상 이수하면 5를 받을 수 있다. 로그인 후 결과 화면은 확인 전 지급을 확정해서 알리지 않는다.
- 학과 그만두기·전체 초기화도 명령으로 저장하며 크레딧 지급 내역은 남긴다.

## 로컬 검증 (2026-11-20)

외부 메일·운영 Supabase 없이 실제 FastAPI 앱, 로컬 TLS SMTP, PostgreSQL 엔진(PGlite)을 연결했다. 테스트용 DB HTTP 어댑터·메일함은 저장소 밖에 있고 제품 코드에는 포함하지 않는다.

1. Chrome에서 비로그인 상태로 컴공 입학 → 미분방정식 3라운드 15문항 이수 → A+와 한 줄 기록, 브라우저 크레딧 5.
2. 이메일 인증 → 가입 → 기록 가져오기. 이름·입학일·A+·메모가 나타나고 계정 크레딧은 0.
3. 이름을 ‘계정 저장 도토리’로 수정하고 저장소 마스코트 PNG를 프로필 사진으로 선택 → 서버 저장.
4. 로그아웃 → 시작 화면, 이름·사진·계정 기록 미표시 → 동일 이메일로 재로그인 → 전부 복원.
5. 별도 origin(`127.0.0.1`, 원래 `localhost`)의 빈 저장소·쿠키 환경에서 동일 계정 로그인 → 이름·사진·A+·메모 복원. 물리적 두 기기가 아니라 저장소와 세션이 분리된 두 환경으로 확인했다.
6. 로컬 DB 어댑터의 쓰기만 실패시킴 → 새 입학 변경이 큐에 남고 ‘연결되면 저장할게요’ 표시. 로그아웃 시도 → 미저장 경고 → 취소. 연결 복구 후 자동 재전송되고 다른 환경에서도 입학 확인.
7. 로그인 상태로 산업디자인 졸업작품 사포질·도색 완료 → 한 줄 기록 → P. 다른 환경에서 새로고침 후 이수 2과목·졸업 1학과·크레딧 5 확인.

자동 검사: 프론트 147개, 백엔드 56개, 빌드 통과. 기존 계정·로그인·신규 기록 SQL 검사 세 묶음 통과. 역할별 접근 차단, 중복 요청, CAS 충돌, 학년·성적 검증, 계정 소유권, 7일 경계, 사진 디코딩, 프로필 충돌, 오프라인 재전송, 여러 창 큐, 로그아웃 실패·미저장 경고를 검사한다.

재검사:

```sh
npm test
npm run build
backend/.venv/bin/python -m unittest backend.test_api
```

로컬 PostgreSQL에 `supabase/checks/supabase_roles.sql` → `supabase/migrations/*.sql`(이름순) → `supabase/checks/account_base.sql`, `login_signup.sql`, `account_records.sql`을 실행한다. 검사 SQL은 테스트 픽스처를 롤백하며 운영 DB에서 실행하지 않는다.

## 운영 반영

이 작업은 #32 위의 #33 → #34 → #35 브랜치 스택이다. #35에는 통합 UI 검증에서 발견한 #33/#34 기록 보호 수정도 포함한다. 로그인 PR부터 순서대로 검토·병합해야 한다. main 직접 푸시와 운영 DB 적용은 하지 않았다.

기존 3개 마이그레이션 다음 `20261120000300_account_records.sql`과 `20261120000400_record_sync.sql`이 필요하다. Vercel 서버 전용 계정 키·정확한 `AUTH_BASE_URL`·이메일 발송 설정은 로그인 문서대로 준비한다. Pillow 12.3.0을 서버 의존성에 추가했다. CSP는 같은 서버 API와 data 이미지 경로를 쓰므로 바꾸지 않는다.
