# 데이터 출처

## 학과·교육과정 (`data/departments.json`)

두 학과의 학년별 과목은 학교가 공개한 공식 교육과정 문서의 [별표1] 교육과정 편성표에서 이수학년 칸을 그대로 옮겼다(2026-11-03 확인).

| 학과 | 문서 | 주소 |
| --- | --- | --- |
| 경희대학교 소프트웨어융합대학 컴퓨터공학부 컴퓨터공학과 | 2026학년도 교육과정 [별표1] 교육과정 편성표 | https://ce.khu.ac.kr/ce25/cmmn/file/fileDown.do?menuNo=21600025&atchFileId=317a0f82d4104052bfa37b7865b6038a&fileSn=1&bbsId=BMSR00048 |
| 경희대학교 예술·디자인대학 산업디자인학과 | 2025 교육과정 [별표1] 교육과정 편성표, [별표7] 교육과정 이수체계도 | https://dc.khu.ac.kr/dc/cmmn/file/fileDown.do?menuNo=15400056&atchFileId=264fb13d9a0a4c17ba986b274cef66be&fileSn=1&bbsId= |

- 컴퓨터공학과: 이수학년이 범위(예: 3-4)인 과목은 시작 학년에 넣었다. 개설학기가 △로만 표시된 학기는 빼고 넣었다(△의 뜻이 문서에 없음). 원문 오타 `메타버스테이터처리`는 문서 그대로 두었다.
- 컴퓨터공학과에서 편성표에는 있지만 2023년 1학기 ~ 2026년 2학기 경희대 학부 종합시간표에 개설 기록이 없어 공개 강의계획서를 찾지 못한 10과목은 뺐다(2026-11-09 사용자 결정). 3학년 몰입심화학습(AI아트테크), 몰입심화학습(AI헬스케어), 4학년 AIoT디지털시스템, 웹보안, 인간-컴퓨터상호작용, 몰입심화학습(SK인텔릭스), 몰입심화학습(딥엑스), 몰입심화학습(알체라), 몰입심화학습(카카오헬스케어), 몰입심화학습(캡스톤실습). 개설 여부는 `hjdd0309/campus_hi`의 `학과데이터/경희대학교_컴퓨터공학부_컴퓨터공학과/강의계획서_목록.csv`(2026-11-08)로 확인했다. 그래서 컴퓨터공학과는 편성표 93과목 중 83과목이다.
- 산업디자인학과: 문서의 이수학년 칸 그대로다.
- 열린 학년의 모든 과목(위에서 뺀 미개설 과목 제외)을 들을 수 있다. 논문·연구연수활동·독립심화학습·몰입심화학습처럼 강의가 아닌 항목도 편성표에 있으므로 그대로 둔다.
- `kinds`는 편성표의 이수구분 칸 그대로다(2026-11-09 확인). 전공기초·전공필수가 다음 학년 해금 조건의 필수과목이고, 적히지 않은 과목은 전공선택이다. 컴퓨터공학과는 [별표1] 순번 1~4 전공기초, 5~18 전공필수(졸업논문(컴퓨터공학) → 데이터의 `졸업논문`). 산업디자인학과는 [별표1] 순번 1~7 전공기초, 8~15 전공필수. 산업디자인학과의 졸업 과제 과목 산업디자인종합설계2는 편성표상 전공선택이지만, 앱에서는 졸업 과제로 졸업에 필요하다.
- `practice`는 학과군 실습 체험을 붙인 과목, `final`은 4학년 졸업 과제 과목이다.
- `building`은 학과가 있는 국제캠퍼스 건물(캠퍼스 지도에서 누르는 건물)이다. 건물 이름은 경희대 공식 캠퍼스맵(https://www.khu.ac.kr/kor/user/contents/view.do?menuNo=200086, 2026-11-09 확인)의 표기 그대로다. 컴퓨터공학과는 강의계획서의 교수 연구실 주소(전자정보대학관), 산업디자인학과는 학과 홈페이지(https://id.khu.ac.kr) 행사 장소(국제캠퍼스 예술디자인대학)와 소속 단과대학(예술·디자인대학)으로 확인했다. 지도에서 건물의 위치·윤곽은 오픈스트리트맵(© OpenStreetMap contributors, ODbL 1.0, 2026-11-09 받음)의 실제 데이터를 쓴다(`scripts/campus-map.mjs` → `frontend/src/campusMapData.js`, 건물마다 오픈스트리트맵 번호는 `campus.js`의 `osm`).

형식 (`departments` 배열의 항목):

| 필드 | 뜻 |
| --- | --- |
| `id`, `school`, `name`, `official_name` | 학과 식별자와 이름 |
| `group` | 학과군(`computing` 또는 `design`). 실습·졸업 과제 체험을 정한다 |
| `source` | 교육과정 문서 제목, 주소, 적용 연도, 확인 날짜 |
| `years` | 학년(`"1"`~`"4"`) → 편성표의 과목 |
| `kinds` | 이수구분: `{"전공기초": [...], "전공필수": [...]}`. 편성표에 있는 서로 다른 과목이어야 한다 |
| `practice`, `final` | 실습 과목, 졸업 과제 과목 |
| `building` | 학과가 있는 국제캠퍼스 건물(공식 캠퍼스맵 표기, `frontend/src/campus.js`의 건물 이름과 같아야 지도에서 열린다) |

서버는 시작할 때 이 형식을 검사하고(`main.check_department`), 맞지 않으면 뜨지 않는다.

## 연습 문제 (`data/lesson_games.jsonl`)

이전 서비스(`hjdd0309/campus_hi`)에서 옮긴 과목별 고정 연습 문제(컴퓨터공학과 20과목, 산업디자인학과 4과목)는 2026-11-09 사용자 결정으로 뺐다(전부 다시 만든다). 파일이 없으면 서버는 고정 문제 없이 뜨고, 해당 과목은 구현 예정으로 보인다. 지난 내용은 git 기록에 있다. 다시 넣을 때 형식은 `frontend/src/lessonGames.js`의 유형별 검사와 같다.

## 이론 수업 문제 은행 (`data/theory_banks.jsonl`)

이론 수업(강의계획서 수업유형의 이론강의 비율 70% 이상, 2026-11-09 사용자 결정)은 고정된 문제 한 세트 대신 과목마다 **문제 은행**을 둔다. 체험할 때마다 화면(`frontend/src/theory.js`)이 은행에서 서로 다른 유형 3개(짝 맞추기, 용어 고르기, OX, 분류하기, 순서 맞추기 중)를 골라 3라운드를 만들고, 문항도 무작위로 뽑는다. 은행이 있는 과목은 `lesson_games.jsonl`에 고정 문제가 있어도 은행을 쓴다.

- 출처: 경희대 수강신청 사이트의 공개 강의계획서 주차별 강의 내용(`source` 필드). 원문은 `hjdd0309/campus_hi`의 `학과데이터/경희대학교_컴퓨터공학부_컴퓨터공학과/강의계획서/`에 있다.
- 검증: AI가 쓰고, 쓰지 않은 별도 에이전트가 `python -m backend.theory_banks blind 과목`으로 만든 정답 없는 문제지를 강의계획서와 함께 푼다. `apply`로 대조해 답이 다르거나 애매·오류로 지적된 항목은 빼고, 남은 것이 형식을 만족하면 `status: "verified"`가 된다. 뺀 항목과 이유는 `check`에 남고 화면에는 보내지 않는다.
- 2026-11-09: 컴퓨터공학과 1학년 이론 수업 5과목(이산구조, 미분적분학, 미분방정식, 선형대수, 실감미디어컴퓨팅기초) 검증 통과. 검증 뒤 미분방정식의 '거듭제곱급수 해법'은 뜻에 용어가 들어가 있어 뺐다.
- 2026-11-09: 컴퓨터공학과 2학년 이론 수업 10과목(신호와시스템, 회로와신호, 확률및랜덤변수, 컴퓨터구조, 논리회로, 기계학습, 게임프로그래밍입문, 풀스택서비스네트워킹, 마이크로서비스프로그래밍, 오픈소스SW개발방법및도구) 검증 통과. 분반·학기마다 주차 내용이 다른 과목은 모든 분반에 공통으로 있는 주제만 썼다. 확률및랜덤변수의 EE21103 강의계획서는 내용이 디지털 통신(Sklar 교재)이라 이 과목과 맞지 않아 근거에서 빼고 EE21101만 썼다. 최신기술콜로키움2는 강의계획서가 초청 특강뿐이라 은행을 만들지 않았다(구현 예정).

| 필드 | 뜻 (상한은 `theory_banks.problems`, `lessonGames.js`의 `cleanTheory`와 같다) |
| --- | --- |
| `course_name`, `title`, `explanation` | 과목, 퀴즈 제목(20자), 배운 내용(120자) |
| `units` | 단원 이름 2~6개(8자). 분류하기의 칸 |
| `terms` | 용어(10자)·뜻(22자)·단원 번호 8~40개. 짝 맞추기·용어 고르기·분류하기에 쓴다. 용어와 뜻은 서로 겹치지 않고, 뜻에 용어가 그대로 들어가면 안 된다. 단원 이름과 낱말이 겹치는 용어(예: 단원 '적분'의 '부분적분')는 답이 보이므로 분류하기에는 내지 않는다(`theory.js`의 `revealsUnit`) |
| `facts` | 문장(60자)·참거짓·해설(80자) 5~40개, 맞는 문장과 틀린 문장 2개 이상씩. OX에 쓴다 |
| `sequences` | 순서가 하나로 정해지는 과정 0~10개: 질문(40자), 단계 4~5개(24자), 해설(120자). 순서 맞추기에 쓴다 |
| `status`, `check` | 검증 상태(`draft`·`verified`·`rejected`)와 검증 기록 |
